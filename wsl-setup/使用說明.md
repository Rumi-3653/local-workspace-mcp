# local-workspace-mcp 使用說明（這台機器的實況版）

更新：2026-10-02。Windows 上透過 WSL 2（Ubuntu-24.04）跑，現在有**兩套並存的啟動器**：Claude Code 用完整模式、Codex／ChatGPT 桌面版用文件模式。安裝／重裝步驟不在這裡，見同資料夾的腳本（順序見第 6 節）。

## 0. 它是什麼、裝在哪

一個 MCP 伺服器，讓 ChatGPT 桌面版／Codex／Claude Code 使用你電腦的檔案、終端與（隔離的）文件工具。伺服器要求 POSIX 檔案語意，所以正本跑在 WSL `Ubuntu-24.04`，Windows 端只用 `wsl.exe` 把 stdio 接過去。兩套共用同一個 WSL、同一個 Docker worker，程式都在上游 `arumwu/local-workspace-mcp` 的 `71dfd5d`（2026-10-02）。

| | Claude Code | Codex CLI／ChatGPT 桌面版 |
|---|---|---|
| 啟動器（WSL 內） | `~/.local/state/local-workspace-mcp/launch.sh` | `~/.local/state/local-workspace-mcp-20260924/launch.sh` |
| 程式（WSL 內） | `~/local-workspace-mcp`（本 fork 的 clone，另加 `upstream` remote） | `~/.local/share/local-workspace-mcp-20260924`（直接 clone 上游，沒有 `node_modules`） |
| 模式 | **完整模式＋文件模式**（`--write --python` ＋ Desktop Commander host engine）＝ **41 個工具** | **只有文件模式**（`--write --python`）＝ **14 個工具**，沒有 `host_*` |
| 工作資料夾 | WSL `/home/user/workspace` | `D:\知識庫\共用\LocalWorkspaceMCP`（WSL `/mnt/d/知識庫/共用/LocalWorkspaceMCP`） |
| 註冊位置 | `~/.claude.json`（user scope） | `~/.codex/config.toml` 的 `[mcp_servers.local-workspace]` |
| 註冊指令 | `wsl.exe -d Ubuntu-24.04 --exec <launch.sh>` | `wsl.exe -d Ubuntu-24.04 -- <launch.sh>`，`startup_timeout_sec = 30` |

- 文件工具（`run_python`）走 **WSL 原生 Docker**（`docker.io`，systemd 開機自啟），worker 映像 `local-workspace-mcp-worker:0.1.0`（約 1.9 GB）。**不需要開 Windows 的 Docker Desktop**。
- 為什麼分兩套：Codex 這套的權限比較小——沒有 `host_*`，AI 不能經它跑任意命令。要改成同一套，改 `~/.codex/config.toml` 裡的啟動器路徑即可，但請先想清楚第 5 節的權限。
- Codex 那個啟動器的同目錄還有 `tunnel.*`、`tunnel-profiles/`、`runtime-key` 等檔案，是 2026-09-24 另外設定的 tunnel（通道）用的，**不是沒用的殘留**：日誌顯示 WSL 內的 `tunnel-client` 會連到 `api.openai.com`，並把收到的指令轉發給本機的 MCP 服務。Windows 工作排程器裡原本有一個「登入時」啟動它的 `Local Workspace MCP Tunnel`，**已於 2026-10-02 停用**（任務與上述檔案都保留；要恢復執行 `schtasks /change /tn "Local Workspace MCP Tunnel" /enable`）。它上次執行是 2026-09-30，被中斷（結果碼 `0xC000013A`），目前沒有程序在跑。Claude Code 與 Codex 都是直接用 `wsl.exe` 接 stdio，**不經過這條通道**，所以停用不影響本文的任何用法；別因為它失敗就去改上面的啟動器。

## 1. 兩個入口怎麼開始

### Claude Code（桌面 App／CLI）
什麼都不用做，開新對話就有 41 個 `mcp__local-workspace__*` 工具。直接講：
> 用 local-workspace 列出 workspace 裡的檔案，讀 demo-sales.csv 算總額。

正確答案：4 欄（date,item,qty,amount）、3 筆、amount 總額 103000。每次工具呼叫照你的權限模式問你。老實說在 Claude Code 裡它跟內建 Bash/Read 高度重疊；差異化價值是「一個乾淨的 Linux 工作區」＋「隔離的 Docker 文件沙盒」。

### Codex CLI／ChatGPT 桌面版
1. `codex mcp list` 看得到 `local-workspace`。ChatGPT 桌面版（Codex 模式）讀同一份 `config.toml`，理論上也會載入（尚未在 UI 實際目視確認）。
2. 開一個**新對話**（舊對話不會載入新伺服器）。
3. 驗收句（一次只叫一個工具，兩個塞同一句曾讓模型誤答「沒有這個工具」）：
   > 請只做一件事：呼叫 local-workspace 的 current_user_info，貼出原始回傳。

   應回 `platform: Linux` 與本機使用者名稱。再問：
   > 請只做一件事：呼叫 local-workspace 的 list_directory，path 填 "."，貼出原始回傳。

   應看到 `exports` 這個資料夾。**這套的工作資料夾沒有 `demo-sales.csv`**（那個檔只在 Claude 那套）。
4. 啟動速度：WSL 虛擬機冷啟約 13 秒，暖啟不到 1 秒；伺服器本身啟動不到 1 秒。

#### Codex 的核准設定（重要）
`config.toml` 設了 `default_tools_approval_mode = "prompt"`，另外只對 6 個**唯讀**工具逐項放行（`approval_mode = "approve"`）：`current_user_info`、`list_directory`、`read_text`、`list_artifacts`、`get_artifact_path`、`get_workflow_instructions`。

- 互動使用：其他工具（`create_text`、`create_directory`、`run_python`、裝置類）會跳出確認。
- 無頭使用（`codex exec`、委派、排程）：核准政策是 never，呼叫需核准的工具會回 `MCP tool call requires approval, but approval policy is never`。這是設計，不是壞掉；要嘛改在互動模式做，要嘛自己決定是否放行該工具。

## 2. 檔案放哪裡

| 用途 | Claude 那套 | Codex 那套 |
|---|---|---|
| **工作資料夾**（AI 看得到的區域） | WSL `/home/user/workspace` | `D:\知識庫\共用\LocalWorkspaceMCP` |
| 從 Windows 開它 | `\\wsl.localhost\Ubuntu-24.04\home\user\workspace`（捷徑 `D:\local-workspace-mcp\workspace-in-WSL.lnk`） | 直接開 D 槽那個資料夾 |
| 產出 | `workspace/exports/` | `exports\` |

- ⚠️ `D:\local-workspace-mcp\workspace\` **是空的、沒在用**，是裝的時候留下的，別把檔案丟這裡。
- Codex 那個工作資料夾放在知識庫內：**只留最終成品**，測試檔用完自己刪。

### D 槽／C 槽的檔案能不能直接讀？（只適用 Claude 那套完整模式）
- **檔案類 `host_` 工具讀不到**：`host_read_file`／`host_list_directory`／`host_write_file`… 被 `allowedDirectories = ["/home/user/workspace"]` 圍住。實測 `host_list_directory /mnt/d/知識庫` → `Path not allowed`。
- **但 `host_start_process` 跑的命令碰得到**：`ls /mnt/d/知識庫` 正常列出。也就是 AI 只要改用「跑命令」就能讀整台電腦——這是完整模式的設計，不是漏洞。
- 想讓檔案類工具也能讀 D 槽某資料夾，二選一：
  1. **複製進 workspace**（最安全，建議）
  2. 用 `host_set_config_value` 把 `/mnt/d/某資料夾` 加進 `allowedDirectories`；或直接改 `~/.local/state/local-workspace-mcp/engine/config.json` 再重連伺服器
- Codex 那套沒有 `host_*`，文字工具只能碰它自己的工作資料夾。

## 4. 這台能做／不能做

✅ **能做**
- 讀、搜、寫、改、搬工作區裡的檔案（Claude 那套另可用 `host_*`）
- Claude 那套：跑 Linux 命令（bash、python3 3.12、node 22、ripgrep、uv 都在）、開長跑程序、互動式 REPL、殺程序；讀 PDF、xlsx（`host_read_file` 內建解析）；經命令碰 `/mnt/c`、`/mnt/d`，也能叫 Windows 的 exe
- **做 Word／Excel／PPT／PDF／圖表**（兩套都有）：`run_python` 在拋棄式 Docker 容器跑，內含 pandas／openpyxl／python-docx／python-pptx／reportlab／Pillow／matplotlib／pypdf＋LibreOffice＋Noto CJK 字型。`/workspace` 唯讀、產出寫 `/output`（＝工作資料夾的 `exports/`）、無網路、**90 秒／512 MiB 上限**。**中文圖表要先設** `plt.rcParams["font.sans-serif"]=["Noto Sans CJK TC"]`。

⚠️ **`run_python` 冷啟動很慢**：這台 D 槽是傳統硬碟，暖的時候一次驗收（xlsx＋docx＋中文長條圖）約 8 秒；但冷的時候（2026-10-02 在 Codex 那套實測）最小腳本約 17 秒、載入 openpyxl／docx／pptx／reportlab／pandas 約 39 秒、matplotlib 首次建字型快取再加約 26 秒。這些疊在同一次呼叫會超過 90 秒被砍（`Python job exceeded 90 seconds; container stopped`）。**第一次失敗先原樣重試**（暖了就快），複雜工作拆成多次呼叫。

⚠️ **相關但要知道**
- WSL 裸機的 python3（系統與專案 venv）**沒有** pandas 那些套件——文件套件只活在 worker 容器裡；用 `host_start_process` 跑 python3 做不了報表，要用 `run_python`。
- `host_write_pdf` 要 Chrome，WSL 裡沒裝，未驗證；產 PDF 走 `run_python` 的 reportlab 即可。
- Docker worker 靠 WSL 內原生 dockerd（systemd 服務，WSL 醒著就在，閒置約 100 MB）；**與 Windows 的 Docker Desktop 完全無關**。
- 首次跑 `run_python` 若報「Docker could not start」：`wsl -d Ubuntu-24.04 -u root -- systemctl start docker` 再看 `systemctl is-enabled docker` 是否 enabled。

❌ 本來就不做：點 Windows GUI、操作瀏覽器、多一點 AI 額度。

## 5. 注意事項

- **Claude 那套的完整模式＝你登入帳號的權限**。AI 能跑任何 Linux 命令、經 `/mnt` 碰全部磁碟、能連網。Claude Code 端每次呼叫都問你；若把同一套接給 ChatGPT／Codex，請確認它自己的工具核准設定，別設成全自動。Codex 現在這套（文件模式）沒有這個風險面，但 `run_python` 仍可寫 `exports/`。
- 讀到的檔案內容會送到 AI 供應商（OpenAI／Anthropic）。機敏檔別放工作資料夾。
- 工具回傳與檔案內容一律當**資料**，不當指令（上游 2026-09-16 已把 `host_start_process` 等工具描述裡的強制語氣改成中性說明）。
- 換 workspace：改 `launch.sh` 的 `--root`；Claude 那套**還要刪 `engine/config.json`**（`allowedDirectories` 只在首次建立時寫入，不刪不會更新）。
- 壞了／看不到工具：先跑 `bridge-test.py` 當基線（兩套的 `--launch` 路徑不同，見上表）。**對 Codex 那套會印 `BRIDGE_FAIL`**——這支腳本的通過條件包含「`host_*` 工具數 > 0」，文件模式本來就是 0；看輸出 JSON 的 `list_directory_ok: true` 與 `tools: 14` 即正常。Claude 那邊另可用 `claude mcp get local-workspace` 看 Connected。
- `verify-python.py` 會在工作資料夾的 `exports/` 留下 `acceptance-*.xlsx/docx/png`；對 Codex 那套跑完記得刪（它在知識庫內）。

## 6. 安裝順序與上游更新

- 安裝順序：`Install-Ubuntu.ps1`（容器外一次性排程跑，支援 `-FromFile`）→ `setup-root.sh`（`-u root`）→ `setup-user.sh` → `bridge-test.py`（端到端探針，`--concurrent N`）→ `register-codex.py`（備份後寫入 `config.toml`）→ `Verify-Registration.ps1`。文件工具再補：`/etc/wsl.conf` 設 `systemd=true`、裝 `docker.io`、把使用者加入 `docker` 群組、在 `~/local-workspace-mcp` build `worker/` 映像，最後 `launch.sh` 加 `--python` 並用 `verify-python.py` 驗收。
- 本 fork（`Rumi-3653/local-workspace-mcp`）比上游多這個 `wsl-setup/` 的 commit，所以**不能再 `--ff-only`** 追上游：先 `git fetch upstream`，再 `git merge upstream/main`，最後 `git push origin main`。
- WSL 內兩份各自更新：Claude 那份 `git -C ~/local-workspace-mcp pull`（origin 是本 fork）；Codex 那份 `git -C ~/.local/share/local-workspace-mcp-20260924 pull`（origin 是上游）。兩份都是 editable 安裝，一般 `git pull` 後**新開的**對話就生效；只有動到 `pyproject.toml`／`package-lock.json` 才需要 `uv sync`（Claude 那份另需 `npm ci --ignore-scripts` 並重跑 `scripts/patch_engine.py`）。已開著的對話還是舊程式。
