# local-workspace-mcp 使用說明（這台機器的實況版）

更新：2026-09-15（同日補裝 Docker worker，`run_python` 文件工具已可用）。安裝／重裝 SOP 不在這裡，見同資料夾的腳本與記憶 `local-workspace-mcp-wsl-install`。

## 0. 它是什麼、裝在哪

- 一個 MCP 伺服器，讓 ChatGPT 桌面版／Codex／Claude Code 使用你電腦的檔案與終端。
- 正本跑在 WSL `Ubuntu-24.04`：程式 `~/local-workspace-mcp`、啟動器 `~/.local/state/local-workspace-mcp/launch.sh`。
- 裝的是**完整模式＋文件模式**（`--write --python` + Desktop Commander host engine）＝ **41 個工具**。文件工具走 WSL 原生 Docker（09-15 補裝：systemd=true + docker.io 29.1.3 開機自啟 + worker 映像 `local-workspace-mcp-worker:0.1.0` 1.9GB），**不需要開 Docker Desktop**。
- 三個客戶端都已註冊，指令一律 `wsl.exe -d Ubuntu-24.04 --exec <launch.sh>`：
  - Claude Code：user scope（`~/.claude.json`）
  - ChatGPT 桌面版 + `codex` CLI：`~/.codex/config.toml [mcp_servers.local-workspace]`，`enabled = true`、`startup_timeout_sec = 60`

## 1. 三個入口怎麼開始

### Claude Code（桌面 App／CLI）
什麼都不用做，開新對話就有 41 個 `mcp__local-workspace__*` 工具。直接講：
> 用 local-workspace 列出 workspace 裡的檔案，讀 demo-sales.csv 算總額。

每次工具呼叫照你的權限模式問你。老實說在 Claude Code 裡它跟內建 Bash/Read 高度重疊；差異化價值是「一個乾淨的 Linux 工作區」＋「跟 ChatGPT 共用同一個 workspace」。

### ChatGPT 桌面版（主要用途）
1. 設定 → MCP 伺服器（或 Codex 分頁的 MCP servers）→ 找 `local-workspace` → 確認已啟用。
2. 開一個**新對話**（舊對話不會載入新伺服器）。
3. 第一次呼叫冷啟約 13 秒（timeout 已設 60s），等一下就好；之後暖啟 <1 秒。
4. 驗收句（workspace 裡已放好 `demo-sales.csv`）：
   > 請列出工作資料夾裡的檔案，再讀取 demo-sales.csv，告訴我欄位和總筆數。
   
   正確答案：4 欄（date,item,qty,amount）、3 筆、amount 總額 103000。讀得到才算真的接上。

### codex CLI
`codex mcp list` 看得到 `local-workspace`；對話裡直接用，不用額外設定。

## 2. 檔案放哪裡

| 用途 | 位置 |
|---|---|
| **工作資料夾**（AI 看得到的區域） | WSL `/home/user/workspace` |
| 從 Windows 開它 | `\\wsl.localhost\Ubuntu-24.04\home\user\workspace`（捷徑 `D:\local-workspace-mcp\workspace-in-WSL.lnk`） |
| 產出 | `workspace/exports/`（第一次產文件才會自動建） |
| ⚠️ `D:\local-workspace-mcp\workspace\` | **空的、沒在用**，是裝的時候留下的，別把檔案丟這裡 |

### D 槽／C 槽的檔案能不能直接讀？
- **檔案類 host_ 工具讀不到**：`host_read_file`／`host_list_directory`／`host_write_file`… 被 `allowedDirectories = ["/home/user/workspace"]` 圍住。09-15 實測 `host_list_directory /mnt/d/知識庫` → `Path not allowed`。
- **但 `host_start_process` 跑的命令碰得到**：09-15 實測 `ls /mnt/d/知識庫` 正常列出。也就是 AI 只要改用「跑命令」就能讀整台電腦——這是完整模式的設計，不是漏洞。
- 想讓檔案類工具也能讀 D 槽某資料夾，二選一：
  1. **複製進 workspace**（最安全，建議）
  2. 用 `host_set_config_value` 把 `/mnt/d/某資料夾` 加進 `allowedDirectories`；或直接改 `~/.local/state/local-workspace-mcp/engine/config.json` 再重連伺服器

## 4. 這台能做／不能做

✅ **能做**
- 讀、搜、寫、改、搬 workspace 裡的檔案
- 跑 Linux 命令：bash、python3 3.12、node 22、ripgrep、uv 都在
- 開長跑程序、互動式 REPL（`python3 -i`）、殺程序
- 讀 PDF、xlsx（`host_read_file` 內建解析，不用另裝）
- 透過命令碰 `/mnt/c`、`/mnt/d`，也能叫 Windows 的 exe（`/mnt/c/Windows/System32/*.exe`）
- **做 Word／Excel／PPT／PDF／圖表**（09-15 起）：`run_python` 在拋棄式 Docker 容器跑，內含 pandas／openpyxl／python-docx／python-pptx／reportlab／Pillow／matplotlib／pypdf＋LibreOffice＋Noto CJK 字型。`/workspace` 唯讀、產出寫 `/output`（＝`workspace/exports/`）、無網路、90 秒／512MiB 上限。**中文圖表要先設** `plt.rcParams["font.sans-serif"]=["Noto Sans CJK TC"]`。09-15 驗收：xlsx＋docx＋中文長條圖一次過（`verify-python.py` 全綠 8.4s）。

⚠️ **相關但要知道**
- WSL 裸機的 python3（系統與專案 venv）**仍然沒有** pandas 那些套件——文件套件只活在 worker 容器裡；用 `host_start_process` 跑 python3 做不了報表，要用 `run_python`。
- `host_write_pdf` 要 Chrome，WSL 裡沒裝，未驗證；產 PDF 走 `run_python` 的 reportlab 即可。
- Docker worker 靠 WSL 內原生 dockerd（systemd 服務，WSL 醒著就在，閒置約 100MB）；**與 Windows 的 Docker Desktop 完全無關**，Docker Desktop 不用開。
- 首次跑 `run_python` 若報「Docker could not start」：`wsl -d Ubuntu-24.04 -u root -- systemctl start docker` 再看 `systemctl is-enabled docker` 是否 enabled。

❌ 本來就不做：點 Windows GUI、操作瀏覽器、多一點 AI 額度。

## 5. 注意事項

- **完整模式＝你登入帳號的權限**。ChatGPT 能跑任何 Linux 命令、經 `/mnt` 碰全部磁碟、能連網。Claude Code 端每次呼叫都問你；ChatGPT 端請確認它自己的工具核准設定，別設成全自動。
- 讀到的檔案內容會送到 AI 供應商（OpenAI／Anthropic）。機敏檔別放 workspace。
- 換 workspace：改 `launch.sh` 的 `--root`，**並刪 `engine/config.json`**（`allowedDirectories` 只在首次建立時寫入，不刪不會更新）。
- 壞了／ChatGPT 看不到工具：先跑 `D:\local-workspace-mcp\wsl-setup\bridge-test.py` 當基線；`claude mcp get local-workspace` 看 Connected；重裝順序見同資料夾腳本。
- 上游 `arumwu/local-workspace-mcp` 更新：`git fetch upstream` 比對，有新版再進 WSL `~/local-workspace-mcp` 拉、`uv sync`、`npm install`。
